# 프론트 → 백엔드 회신 (docs/handoff-from-backend-505.md §2, 2026-08-20)

프론트 세션이 작성. `docs/handoff-from-backend-505.md` §2가 요구한 세 결정에 대한 답이다.
spec 049(2단계 주문 방법 학습을 3단계 대본에서 분리) 착수 전에 이 문서 하나만 읽으면 된다.

---

## (1) 화면 게이팅 — 숨기지 않는다, 비활성 + 이유를 붙인다

**2단계에서는 손절·익절 프리셋 컨트롤을 비활성으로 두고 이유를 한 줄 붙인다. 숨기지 않는다.**

이 화면에는 이미 같은 패턴이 있다 — "예약 매도" 탭은 지금 못 쓰지만 지우지 않고 어둡게 둔 채
"실전에서 손절·익절 가격을 미리 걸어두는 기능인데, 여기서는 자동으로 만들어져서 따로 걸지
않는다"는 문장을 바로 아래 붙인다(`AttemptTutorialFlow.tsx`의 `reservedSellNoteId` 자리).
매수/매도 토글도 지금 못 누르는 쪽을 지우지 않고 남긴다 — "실전 화면에서 처음 보는 컨트롤이
되면 안 된다"는 게 이 화면 전체의 원칙이다. 2단계에서 프리셋을 숨기면 3단계에 처음 들어온
사용자가 "이게 언제 생겼지"로 당황한다.

**3단계에서는 주문 방법(시장가·지정가) 선택을 그대로 열어 둔다 — 되돌아가서 막지 않는다.**
2단계가 이미 두 방식을 다 가르쳤으니 3단계에서 굳이 하나로 제한할 이유가 없다. 지금 코드도
이미 이렇게 돼 있다(시장가·지정가 토글은 3단계에서도 항상 활성).

## (2) 2→3단계 전환 — 사용자 버튼. 자동 호출 아님

**조건(`tutorialStageProgress` 완료 + 보유 없음)이 갖춰지면 CTA 버튼을 보여주고, 사용자가
눌러야 `POST .../advance-script`를 부른다.**

이유는 이 코드베이스가 되돌릴 수 없거나 눈에 띄게 상태를 바꾸는 동작마다 이미 지키고 있는
관례다 — "처음부터 다시 시작"은 확인창을 거치고, 완료 결과는 사용자가 "완료 기록 보기"를
눌러야 다시 열린다. 조건 충족 즉시 자동으로 3단계로 넘기면, 사용자가 지정가 주문을 걸어 둔
채 딴짓하다 돌아왔을 때 자기도 모르게 대본이 바뀌어 있는 경험을 하게 된다(2단계는 대본 없는
±12% 사인파, 3단계는 실제 이야기라 체감 차이가 크다). 버튼 하나면 이 위험이 없다.

버튼 문구·확인창 필요 여부는 실제 구현 때 정하면 된다 — 다만 "완료"류 확인창(`ConfirmDialog`,
"정리하고 다시 시작합니다")과는 톤이 달라야 한다. 이건 되돌릴 수 없는 손실이 아니라 앞으로
나아가는 선택이라, 막는 어조보다는 "3단계로 가기" 같은 초대형 CTA가 맞다.

## (3) `scenarioStage: "ORDER_BASICS"` — 대본 UI를 null과 동일하게 취급한다

지금 화면은 `scenarioStage !== null`을 "대본 UI를 그린다"의 판정 기준으로 쓴다
(`BreakingNewsCrawl`·`ScenarioEventFeed`·`ScenarioStatusLine` 셋 다). **`ORDER_BASICS`는 이
셋 모두에서 `null`과 똑같이 취급한다** — 즉 판정식을
`scenarioStage !== null && scenarioStage !== 'ORDER_BASICS'`로 바꾼다.

이유는 2단계 계약 자체다 — "사건이 없다"(`causeStatus`는 항상 `NONE_KNOWN`, `revealedEvents`는
항상 빈 배열). 사건 패널을 그대로 띄우면 "다음 움직임을 기다리는 중입니다"처럼 아무 내용 없는
줄만 계속 보여주게 되고, 이 기능이 지금까지 지켜온 원칙(서버가 준 사실만 그린다, 없는 이야기를
지어내지 않는다)과 어긋난다. 대신 그 자리에는 "지금은 주문 방법을 연습하는 자리입니다" 같은
목적 설명 한 줄을 넣는다 — 이건 사건이 아니라 화면 자체의 안내라 서버 계약과 무관하게 프론트가
정할 수 있다.

`StepRail`(1~4단계 표시)은 건드리지 않는다 — 2단계는 여전히 "2. 구매하기"로 표시되고,
`ORDER_BASICS`는 그 안에서 사건 없이 주문 연습만 하는 하위 상태로만 다룬다.
