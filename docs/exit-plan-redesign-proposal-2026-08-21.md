# 손절·익절 체험 재설계 제안 (2026-08-21)

프론트 세션이 사용자 피드백을 받아 작성. 3단계(041 이야기) 튜토리얼에서 손절·익절을 "고르는
방식"과 "겪는 방식" 둘 다 지금과 다르게 가자는 제안이다. 두 축 다 기존 spec(041·042)의 명시적
결정을 뒤집으므로, 새 spec 없이는 구현하지 않는다 — 이 문서는 그 spec의 입력 초안이다.

## 배경

지금 3단계는 두 가지를 이렇게 한다.

1. **손절·익절 고르기** — 매수 폼 안에 조심스럽게(-2%·+3%)/보통(-3%·+5%)/느긋하게(-5%·+8%)
   프리셋 3개 중 하나를 매수 전에 고른다. 자유 숫자 입력은 없다(`042-tutorial-exit-preset`
   spec EXITPRESET-001, 초보자에게 빈칸을 주면 그 자리에서 멈춘다는 이유로 의도적으로 배제).
   실전 화면(`pages/Trade.tsx`)의 매도 쪽 "예약 매도" 탭(손절 비율·익절 비율을 각각 자유
   입력하는 UI)은 튜토리얼에도 자리는 있지만 항상 비활성이다 — 손절·익절선은 매수 체결 순간
   서버가 자동으로 만들고 자동으로 예약까지 걸기 때문이다(`TUTORIAL-FLOW-008`).
2. **손절·익절 겪기** — 대본은 손절선·익절선을 둘 다 지나가도록 짜여 있지만(`041` plan.md
   §도달 조건), 사용자가 실제로 둘 다 겪는 것은 **강제되지 않는다**. 완료 조건은 "매수 → 관찰
   → 매도(원인 불문) → 복기" 한 사이클뿐이다(`SCENARIO-014`). spec 스스로 이걸 잔여 위험으로
   적어 뒀다 — "손절 후 그냥 나가는 사용자는 익절을 배우지 못한 채 끝난다. 완화는 프론트 안내와
   완료 화면의 사후 대조뿐이며, 서버가 할 수 있는 건 여기까지다"(spec.md 549행 부근).

사용자(제품 오너)가 실사용 중 이 두 가지에 문제를 제기했다 — 프리셋 고르는 시점·방식이 실전
화면과 달라 혼란스럽고, 무엇보다 **손절과 익절을 "둘 다 실제로 겪는 것"이 이 튜토리얼의 핵심
가치인데 지금은 보장되지 않는다.**

## 제안

### A. 손절·익절 입력 방식 — 실전 화면과 동일한 자리·동일한 UI로

- 매수 화면에서는 프리셋 픽커를 완전히 뺀다. 시장가·지정가만 고른다(실전 화면과 동일).
- 매도 화면의 "예약 매도" 탭을 튜토리얼에서도 실제로 켠다. 실전과 같은 UI(손절 비율·익절
  비율을 각각 슬라이더/숫자로 입력)를 쓰되, **손절은 -2%~-5%, 익절은 +3%~+8% 범위로 막는다**
  — 기존 세 프리셋의 최솟값·최댓값을 그대로 범위의 경계로 쓴 것이다.
- 손절 비율과 익절 비율은 **서로 독립적으로** 고른다(예: 손절 -5% + 익절 +3% 같은 조합도
  가능). 셋 중 하나만 고르는 게 아니라 두 축을 각자 정하는 실전 방식을 그대로 따른다.

### B. 손절·익절 체험 — 유도가 아니라 보장

- 지금은 재진입(다시 매수)이 "유도"만 되고 강제되지 않는다(spec.md 잔여 위험 5). 이 제안은
  **한 번의 실행(run) 안에서 손절과 익절을 각각 최소 1회는 반드시 겪도록** 만든다 — 예를 들어
  첫 진입이 손절로 끝나면 다음 재진입에서는 반드시(또는 대본이 강하게 개입해) 익절을 겪게
  하는 식이다. 순서(손절 먼저·익절 나중, 또는 그 반대)는 열린 질문 — 아래 참고.
- 완료 조건에도 "손절 1회 + 익절 1회를 모두 겪었는가"가 새 전제로 들어가야 한다(지금은
  SCENARIO-014가 "새 전제조건을 추가하지 않는다"고 명시하는데, 이 부분과 정면으로 부딪힌다 —
  041을 고치거나 별도 조건으로 얹어야 한다).

### C. 체험 직후 — 크게, 실제 결과와 반사실을 나란히

- 손절을 겪은 직후, 익절을 겪은 직후 각각 **큰 팝업**을 띄운다. 오늘 만든 2단계 "지금 할 일"
  팝업(`TutorialModal`, 어두운 배경·중앙 카드·ESC로 닫기)과 같은 톤이지만 더 크게, 안에 박스
  두 개를 나란히 둔다.
  - **박스 1 (실제 결과)**: "손절선(-3%)에 닿아 이 정도에서 정리됐습니다" — 설정한 폭대로
    처리된 실제 손익.
  - **박스 2 (반사실)**: "손절을 안 걸었다면" — 그 뒤로도 계속 들고 있었을 때의 결과(더 큰
    손실로 이어졌을 수 있음을 보여줌). 익절 쪽은 반대로 "더 오를 수도 있었지만, 안 걸었다면
    이렇게 됐을 수도 있다"는 식.
  - 이 반사실 계산 자체는 이미 있다 — `unrealizedPnlIfHeld`(안 팔았다면 평가손익) 필드가
    지금도 완료 화면의 `EntryComparison`에서 쓰인다. 손절·익절을 **겪는 바로 그 순간**으로
    당겨서 크게 보여주자는 게 이번 제안의 핵심이다.

| 손절·익절은 프리셋 3개 중 택1, 자유 입력 없음 | `042-tutorial-exit-preset` EXITPRESET-001 | 자유 입력(범위 제한)으로 되돌림 |

## 필요한 백엔드 작업 (프론트 세션 추정, 백엔드 세션 확인 필요)

- 매수 후 손절·익절 예약(OCO)을 사용자가 직접 걸 수 있는 API. 지금은 자동 생성 경로만 있다.
- 041 대본의 재진입 로직을 "유도"에서 "강제/보장"으로 바꾸는 상태 전이 변경 — 첫 진입 결과에
  따라 다음 진입이 반드시 반대쪽(손절 → 익절, 또는 익절 → 손절)을 겪도록 대본을 조정하거나
  분기해야 한다.
- (선택) 손절·익절 각각의 "겪었는가" 플래그를 attempt 단위로 추적 — 완료 판정에 쓰려면 필요.

## 결정된 것 (2026-08-21, 제품 오너 확인)

- **"강제"의 강도는 (b)다** — 손절 뒤 재구매를 강하게 권하는 배너/팝업은 띄우되, 화면을
  잠그지는 않는다. 사용자가 끝까지 재구매를 안 하고 나가면 그냥 미완료(둘 다 겪기 기준으로는)
  로 남는다. 완료 조건·보상 지급을 이 미완료 상태로 막을지는 아래 열린 질문 3에서 마저 정한다.

## 열린 질문

1. 손절이 먼저 오고 익절이 나중인가, 아니면 순서를 랜덤/양방향으로 둘 다 지원하는가?
2. 첫 진입이 익절로 끝나면(즉 손절을 안 겪고 이익부터 봄) 그다음 반드시 손절을 겪게 만드는
   것도 같은 무게로 강제하는가 — 사용자가 "이익 보고 그만두고 싶다"를 존중할 자리는 없는가?
3. 완료 화면(전체 튜토리얼 종료)의 보상 지급 조건도 "손절+익절 각 1회"로 강화하는가, 아니면
   보상은 지금처럼 한 사이클로 두고 이 강제는 "학습 완료"라는 별도 트랙으로 두는가?
4. 재진입을 강제한다는 게 정확히 뭘 뜻하는가 — 매도 후 자동으로 다시 매수하는 것까지는 아닐
   테니(그건 사용자 행동이 아니게 된다), 화면을 막고 "다시 사야 다음으로 넘어간다"는 식의
   UI 잠금인가?
